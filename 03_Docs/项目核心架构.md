> 项目：TC264 巡线小车 + 元器件视觉识别 + 路口遍历（右手法则）
> 主控：Infineon TC264D (AURIX, 200MHz)
> 摄像头：MT9V03X 总钻风 (188×120 灰度)
> 编译器：TASKING (AURIX Development Studio)
> 更新日期：2026-07-05

### 像素分辨率链

```
MT9V03X 原始:     188 × 120  (灰度, uint8)
       ↓ compressimage() 中心裁切
压缩图像:          100 × 60   (灰度, uint8)
       ↓ turn_to_bin() OTSU二值化
二值图像:          100 × 60   (二值, 0/255)
       ↓ median_filter + image_filter
滤波后:            100 × 60   (二值, 0/255)
       ↓ basic_line_tracking
边界/中线:         3 × 60     (int16 数组)
       ↓ track_get_error
转向偏差:          1 × int16

元器件识别 (独立路径):
  原始 188×120 → 裁取 120×120 窗口 → 局部OTSU → 形态学腐蚀
  → 连通域分析 → 11维特征提取 → 评分分类器 → 多帧确认
```

## 二、第一层：图像采集与预处理

### 2.1 原始图像来源

- **文件**: [image.h](code/image.h), [image.c](code/image.c)
- **数据**: `mt9v03x_image_1[120][188]` — DMA 从 MT9V03X 传感器直接搬运，8位灰度
- **触发**: VSYNC 中断置 `mt9v03x_finish_flag_1`，主循环轮询 `mt9v03x_tft180_check_finish()`
- **像素值**: 0=暗（蓝色赛道背景），255=亮（白色赛道线）

### 2.2 `compressimage()` — 中心裁切

| 项目 | 说明 |
|------|------|
| 输入 | `mt9v03x_image_1[120][188]` |
| 输出 | `Image_use_zip[60][100]`（局部静态缓冲） |
| 算法 | 中心裁切：行偏移 `(120-60)/2=30`，列偏移 `(188-100)/2=44`，`memcpy` 逐行复制 |
| 目的 | 裁掉边缘畸变，聚焦赛道 ROI |

### 2.3 `otsuThreshold()` — 全局大津法阈值

| 项目 | 说明 |
|------|------|
| 输入 | 灰度图像 + 尺寸 |
| 输出 | `uint8` 阈值 |
| 算法 | 标准 OTSU：256-bin 直方图 → 遍历每个候选阈值 → 计算类间方差 `wB·wF·(mB−mF)²`，取最大值 |
| 保护 | 动态下限 `max(MinValue+10, 45)`，防止极暗场景阈值崩塌 |
| 关键 | 使用 `uint64` 防溢出（188×120=22560 像素空间） |

### 2.4 `turn_to_bin()` — 二值化

| 项目 | 说明 |
|------|------|
| 输入 | `Image_use_zip[60][100]` |
| 输出 | `bin_image[60][100]`（全局，255=白/赛道线，0=黑/背景） |
| 算法 | OTSU 阈值 + `image_base` 偏移（默认-10）→ 逐像素比较，4路展开加速 |

### 2.5 `median_filter()` — 中值滤波

| 项目 | 说明 |
|------|------|
| 输入/输出 | `bin_image[60][100]`（原地修改） |
| 算法 | 3×3 滑动窗口：9邻域和 ≥1275（≥5个白像素）→输出255，否则0 |
| 实现 | 行指针轮转（`prev/curr/next`），避免 `memcpy` |
| 目的 | 去除二值化后的椒盐噪声 |

### 2.6 `image_filter()` — 形态学滤波

| 项目 | 说明 |
|------|------|
| 输入/输出 | `bin_image[60][100]`（原地修改） |
| 算法 | 单次合并腐蚀+膨胀：8邻域全白但中心黑→填洞（膨胀）；8邻域最多1白但中心白→去斑（腐蚀） |
| 目的 | 连接赛道线细小断点 + 去除孤立噪点 |

## 三、第二层：巡线导航

### 3.1 整体流程

- **文件**: [track_way.c](code/track_way.c), [track_way.h](code/track_way.h)
- **输入**: `bin_image[60][100]`（滤波后二值图）
- **输出**: `left_border[60]`, `right_border[60]`, `center_line[60]`, `track_error`, `track_element_type`

```
basic_line_tracking()       逐行边界搜索，计算中线
        ↓
detect_element_features()   双区域纵向扫描 + 顶部/底部横向扫线
        ↓
identify_element_and_supplement()  元素分类 + 补线
        ↓
update_align_state()        弯道进入/退出状态机
        ↓
track_get_error()           加权偏差计算
```

### 3.2 `basic_line_tracking()` — 逐行边界搜索

| 项目 | 说明 |
|------|------|
| 搜索方向 | 从下往上，最多 `TRACK_SCAN_ROWS=45` 行 |
| 中心预测 | `confidence≥3`：全动量外推 → `confidence≥1`：半动量 → `confidence=0`：无外推 |
| 搜索窗口 | 高置信度窄窗口（±12px），低置信度全宽搜索（±49px） |
| 左边界 | 从左到右搜索 0→255 跳变 |
| 右边界 | 从右到左搜索 255→0 跳变 |
| 单边丢线 | 用赛道宽度 `smooth_rw`（EMA 1/5）推算缺失边界 |
| 全部丢线 | 短期(<8行)：动量外推 + 快速衰减；长期：回图像中心 |
| 中线滤波 | 2帧 EMA 平滑 |
| 置信度 | 两边找到 +1，丢线 −2，上限10 |

### 3.3 元素检测与分类（精简版：电路图赛道专用）

| 扫描 | 范围 | 目的 |
|------|------|------|
| 顶部横向扫线 | 行0~14 | 判断上方是否有引导线（直道/T形） |
| 底部横向扫线 | 行50~59 | 获取底部中线坐标 |
| 内区纵向扫线 | 最边缘12列 | T形节点特征（单侧跳变） |
| 外区纵向扫线 | 最边缘25列 | 钝角弯特征（保留备用） |

**元素类型（精简为6种）**：

| 类型 | 值 | 含义 | 车的反应 |
|------|-----|------|---------|
| `ELEMENT_NONE` | 0 | 正常直道 | 正常巡线 |
| `ELEMENT_COMPONENT` | 1 | 检测到元器件 | 直行压过，不识别具体类型 |
| `ELEMENT_T_JUNCTION` | 2 | T形路口 | 右手定则决策方向 |
| `ELEMENT_RIGHT_ANGLE` | 3 | 直角弯 | 转弯 |
| `ELEMENT_CROSS` | 4 | 十字路口 | 保留备用 |
| `ELEMENT_BREAK` | 5 | 断路 | 死路检测 |

**决策优先级**：

| 条件 | 判定 | 补线策略 |
|------|------|---------|
| 内区单侧有 + 顶部无 | 直角弯 | 从跳变行到底部边缘画线 + 底部强制推边 |
| 顶部有 + 仅单侧内区有 | **T形路口** | 偏向支路方向补线（右手定则入口） |
| 两侧内区都有 + 顶部有 | 十字 | 顶部中点到底部中点直连 |
| 内区无 + 顶部有 + 宽度42-50px | **元件** | 不补线，直行压过 |
| 内区无 + 顶部有 + 宽度≤42px | 直道 | 顶部中点到底部中点直连 |
| 全部标志为0 + 中线偏移>20 | 直角弯（内区漏检） | 激进补线 + 底部推边 |
| 全部标志为0 + 中线偏移≤20 | 断路 | 不补线，保持方向 |

**关键设计**：元件检测通过赛道宽度异常判断，不识别具体元件类型

### 3.4 `track_get_error()` — 加权偏差

| 项目 | 说明 |
|------|------|
| 行数 | 直角弯8行，钝角弯/十字10行，直道10行 |
| 权重 | 越靠近底部的行权重越大，`weight = 行号差值` |
| 输出 | `track_error = Σ(center_line[i]−image_w/2) × weight / Σweight` |

### 3.5 `update_align_state()` — 弯道回正状态机

```
ALIGN_NONE ──(进入弯道)──→ ALIGN_CURVE_IN
                                │ (检测到出口)
                                v
                          ALIGN_CURVE_EXIT ──(偏差大)──→ ALIGN_FORCE
                                │                            │
                                └──(对齐稳定8帧)──→ ALIGN_NONE ←──┘
```

- 连续弯道检测：钝角弯持续30帧以上标记 `is_continuous_curve`
- 强制回正：直接覆盖底部6行的 `center_line`，每帧拉回2px

### 3.6 右手法则路口遍历（电路图赛道核心）

**数据结构**：

```c
typedef struct {
    int32 seg_distance;       // 段距离（编码器脉冲，路口指纹）
    int32 abs_distance;       // 绝对距离（回溯备用）
    uint8 dirs_available;     // 可走方向位掩码
    uint8 dirs_tried;         // 已走过方向位掩码
    uint8 entry_dir;          // 进入方向
    uint8 backtrack_count;    // 回溯次数
} JunctionRecord;
```

**方向编码**：

| 方向 | 编码 | bit位 |
|------|------|-------|
| 直行 | 0 | bit0 |
| 左转 | 1 | bit1 |
| 右转 | 2 | bit2 |

**决策优先级**：右(2) > 直(0) > 左(1)

**路口类型与可走方向**：

| 路口类型 | dirs_available | 说明 |
|---------|---------------|------|
| T形（主线+右侧支路） | 0b101（直+右） | 右手定则优先右转 |
| T形（主线+左侧支路） | 0b011（直+左） | 右手定则选左转 |
| 十字 | 0b111（直+左+右） | 右>直>左 |
| 直角弯 | 0b110 或 0b011 | 只能转向 |

**两级距离匹配**：
1. 段距离匹配（正常行驶）：容差 80 脉冲
2. 绝对距离匹配（回溯时）：容差 300 脉冲

**回溯保护**：`MAX_BACKTRACK=3`，防止死循环

## 四、第三层：元器件识别

### 4.1 整体流程

- **文件**: [component_recognition.c](code/component_recognition.c), [component_recognition.h](code/component_recognition.h)
- **触发**: 主循环双窗口扫描（冷路径，非每帧执行）
- **输入**: `mt9v03x_image_1[120][188]`（原始灰度图） + 扫描位置（图像坐标）
- **输出**: `ComponentResult`（类型 + 置信度0-100 + 位置 + 估算物理尺寸）

```
坐标映射 (60×100 → 188×120)
        ↓
extract_window()        从原始灰度图截取 120×120 窗口
        ↓
local_otsu()            窗口内局部OTSU二值化
        ↓
morph_erode_3x3(1轮)   腐蚀弱化细赛道线
        ↓  (area<10时回退到原始二值图)
connected_component_analysis()  并查集连通域标记 + 11维特征提取
        ↓
classify_component()    v13评分分类器 (11种元器件)
        ↓
component_confirm_result()  多帧确认 (连续2帧同类型)
```

### 4.2 `extract_window()` — 窗口截取

| 项目 | 说明 |
|------|------|
| 输入 | 原始灰度图 `mt9v03x_image_1[120][188]` + 窗口中心(相机坐标) |
| 输出 | `win_binary[120][120]`（灰度值） |
| 边界处理 | 越界时 clamp 到图像边界内 |
| 内存 | 120×120 = 14.4KB |

### 4.3 `local_otsu()` — 局部大津法

| 项目 | 说明 |
|------|------|
| 输入 | `win_binary[120][120]`（灰度，会被覆盖为二值） |
| 输出 | 阈值 + `win_binary` 原地转为二值 (0/255) |
| 算法 | 标准 OTSU，256-bin 直方图，类间方差最大化 |
| 与全局OTSU区别 | 仅在120×120窗口内计算，自适应局部光照 |

### 4.4 `morph_erode_3x3()` — 形态学腐蚀

| 项目 | 说明 |
|------|------|
| 输入/输出 | `win_binary[120][120]`（原地修改） |
| 算法 | 3×3 全白保留：仅当9邻域像素**全部**为255时保留为255，否则置0 |
| 迭代次数 | 1轮 |
| 效果 | 细赛道线(<5px)边缘被移除→连接断开；块状元器件(>15px)仅缩小一圈→保持独立 |
| 回退 | 腐蚀后 area<10 → 用 `win_original` 备份重做连通域分析 |
| 内存 | 14.4KB (`win_original[120][120]` 静态缓冲) |

### 4.5 `connected_component_analysis()` — 连通域分析

| 项目 | 说明 |
|------|------|
| 算法 | 两遍扫描 + 并查集（Union-Find），路径压缩 + 按秩合并 |
| 标签上限 | 255（`uint8` 不足以表示更多标签） |
| 输出 | 最大连通域的包围框 + **11维特征** |

**11维特征列表**：

| 特征 | 类型 | 说明 |
|------|------|------|
| `bbox_x/y/w/h` | int16 | 包围框左上角+宽高 |
| `area_px` | int16 | 白色像素总数 |
| `aspect_ratio` | float | 宽/高比 |
| `fill_density` | float | 白色像素/(bbox宽×bbox高) |
| `col_segments` | int16 | 垂直列分段数（有多少列有白色像素） |
| `row_segments` | int16 | 水平行分段数（有多少行有白色像素） |
| `col_profile[120]` | uint8 | 每列白色像素统计（列投影直方图） |
| `row_profile[120]` | uint8 | 每行白色像素统计（行投影直方图） |
| `top_bottom_ratio` | float | 上半宽度/下半宽度 (>1上宽下窄, <1上窄下宽) |
| `symmetry_score` | float | 左右对称性 0-1 |
| `center_x/y` | int16 | 在原始图像中的中心坐标 |

### 4.6 `classify_component()` v13 — 评分分类器

**设计原则**：

1. **特征可靠性分层**（赛道线污染对各特征影响不同）：

| 层级 | 特征 | 权重 | 受污染程度 |
|------|------|------|-----------|
| T1 | rows, cols, area | 25 | 几乎不受影响 |
| T2 | aspect_ratio, fill_density | 20 | 轻度影响 |
| T3 | symmetry | 12 | 中度影响 |
| T4 | tb_ratio, row_peak_ratio, row_var | 8 | 严重影响（仅做辅助参考） |

2. **线性截断评分函数 GS**（纯整数，绝不产生负分）：

```
GS(val, center, width, max_score) = max_score × max(0, 1 − |val−center|/width)

纯整数实现: max_score × (width − |val−center|) / width
当 val==center: max_score 分
当 |val−center|≥width: 0 分
```

3. **每种元件有1-2个"签名特征" + 混淆抵抗**：

| 元件 | 签名特征 | 易混淆类型 | 区分策略 |
|------|---------|-----------|---------|
| 电阻 | ar>120 + 对称 | 电源 | density>55 软惩罚（排除高密度） |
| 电容 | rows=2-4 | 三极管 | row_peak>18 软惩罚（排除十字形） |
| 电感 | density<0.25（极低） | 电池 | density>35 软惩罚 |
| 三极管 | row_peak高 + T2确认 | 电容 | row_peak<15 软惩罚 |
| 二极管 | \|tb−1.0\| 大（双向） | 对称件 | tb_dist<25 软惩罚 |
| 开关 | rows=2 | — | rows≠2 扣15分 |
| 电池 | rows≥4 | 电感 | density<10 软惩罚（排除极低密度） |
| 接地 | tb>1.3 | 运放 | density>55 软惩罚（排除高密度） |
| 电流表 | ar≈1.1（近圆） | 电源 | density>50 软惩罚（排除高密度） |
| 电源 | density>0.45（高密度） | 电阻 | density<30 软惩罚（排除低密度） |
| 运放 | tb>1.5 + density高 | 接地 | tb<115 软惩罚（排除中等tb） |

4. **软惩罚替代硬悬崖**：

```c
// 旧 (v12): 硬悬崖
if (i_den > 40) s -= 15;   // 密度 40→41 突变 −15

// 新 (v13): GS软过渡
if (i_den > 55) s -= GS(i_den, 55, 20, 12);  // 密度55得0, 75得−12, 平滑
```

5. **差距置信度**：

```
第一名−第二名 ≥ 25 → conf = 绝对分 × 100%  (明确)
第一名−第二名 ≥ 15 → conf = 绝对分 × 80%   (较明显)
第一名−第二名 ≥ 8  → conf = 绝对分 × 60%   (略有优势)
第一名−第二名 < 8  → conf = 绝对分 × 40%   (几乎平手)
```

最低阈值: `best_score < 5` → `COMPONENT_UNKNOWN`

### 4.7 `component_confirm_result()` — 多帧确认

| 项目 | 说明 |
|------|------|
| 机制 | 环形缓冲保留最近 `CONFIRM_FRAMES=2` 帧结果 |
| 确认条件 | 连续2帧类型一致且不为 NONE/UNKNOWN |
| 输出 | `g_confirmed_valid=1` + `g_confirmed_result` |
| 目的 | 消除单帧误判导致的类型跳变 |

### 4.8 内存使用

| 缓冲区 | 大小 | 类型 | 用途 |
|--------|------|------|------|
| `win_binary[120][120]` | 14.4KB | static | 窗口图像（灰度→二值） |
| `win_original[120][120]` | 14.4KB | static | 腐蚀回退备份 |
| `win_labels[120][120]` | 28.8KB | static | 连通域标记（int16） |
| **总计** | **57.6KB** | | TC264 有 256KB RAM，余量充足 |

### 5.2 WiFi SPI 图传

- **文件**: [wifi_image_transfer.c](code/wifi_image_transfer.c), [wifi_image_transfer.h](code/wifi_image_transfer.h)
- **协议**: 逐飞助手（SeekFree Assistant）图传协议，WiFi SPI 模式
- **目标**: PC 上位机 `10.221.147.220:8086`（TCP）

**叠加功能** (`WIFI_TRANSFER_OVERLAY_ENABLE=1`)：

1. 复制 `bin_image` 到 `overlay_image[60][100]`
2. 先画识别文字（`wifi_image_transfer_overlay_result` 清除顶部7行 + 3×5点阵字体）
3. 画结果边框
4. 画两个扫描窗口角标（┌┐└┘形状，6px短线）
5. 通过 WiFi SPI 发送 `overlay_image`

**发送间隔**: `WIFI_TRANSFER_SEND_INTERVAL=1`（每帧都发）

## 六、第五层：主循环

### 6.1 文件

- [cpu0_main.c](user/cpu0_main.c) — `core0_main()`

### 6.2 初始化顺序

```
clock_init() → debug_init() → TFT180 → WiFi图传 → IMU660RA
→ MT9V03X摄像头 → 边界线配置 → 双电机 → 编码器
→ PIT定时器(10ms) → 转向PID(位置式PD) → 速度PID(增量式PI)
→ 元器件识别模块 → 全局中断使能 → 起步斜坡加速
```

### 6.3 主循环（每帧）

```
while(TRUE):
    1. encoder_update()                        编码器采样
    2. 等待 mt9v03x_finish_flag                帧同步
    3. compressimage()                         188×120 → 60×100
    4. turn_to_bin()                           OTSU 二值化
    5. median_filter()                         3×3 中值滤波
    6. image_filter()                          形态学去噪
    7. track_find_line()                       巡线 + 元素检测 + 补线
    8. track_get_error()                       加权偏差
    9. 路口遍历: 编码器距离更新 + 路口注册 + 右手定则决策
  10. 元器件识别 (多位置扫描)                   窗口1=中线, 窗口2=±12px偏移
  11. component_confirm_result()              多帧确认
  12. adjust_steering_pid() + pid_calculate() 自适应PID转向
  13. 路口转弯执行（覆盖PID输出）               强制偏差 + 减速
  14. IMU 转向补偿 + 坡道补偿 + 侧倾保护
  15. 差速驱动: L/R_duty = target ± steer ± IMU
  16. TFT180 显示 bin_image
  17. WiFi 叠加发送 overlay_image
  18. 清除采集标志
```

### 6.4 路口遍历集成

| 步骤 | 代码位置 | 功能 |
|------|---------|------|
| 编码器距离更新 | `junction_update_distance()` | 每帧累计编码器脉冲 |

| 死路检测 | `junction_on_dead_end()` | 连续30帧无有效赛道 → 掉头 |

| 回溯 | 距离指纹匹配 | 段距离(80容差) + 绝对距离(300容差) |
   12. IMU 转向补偿 + 坡道补偿 + 侧倾保护
   13. 差速驱动: L/R_duty = target ± steer ± IMU

```

### 6.4 双窗口扫描策略

| 窗口 | 位置 | 目的 |
|------|------|------|
| 窗口1 | `track_center_x`（赛道线底部10行平均） | 捕捉组件主体 |
| 窗口2 | `track_center_x + offset`（偏移±12px沿赛道方向） | 捕捉组件侧面/边缘 |
| 选择 | 取两窗口最高置信度结果（≥5） | |
| 提前终止 | 任一窗口置信度 ≥70 时跳出 | |
